# DOMNA Match Server 2.0 · Back4App Containers

1. فك ضغط الحزمة على جهازك. ارفع الملفات المستخرجة إلى الفرع المرتبط بتطبيق Back4App الحالي. اجعل `Dockerfile` و`server/` و`packages/` في جذر البناء نفسه. من واجهة GitHub استخدم **Add file → Upload files** واسحب محتويات المجلد المستخرج، بما فيها المجلدات الفرعية.
2. افتح تطبيقك الحالي في **Back4App Containers**. اجعل **Root** هو جذر المستودع إذا وضعت الملفات فيه. احتفظ بإعدادات البيئة الحالية. قيمة `FIREBASE_PROJECT_ID` لمشروع دومنا هي `domina-b5ec1`. يستمع Docker افتراضيًا على المنفذ 8080. يحوي `Dockerfile` خطوة إنشاء `/out` قبل ترجمة ملف الخادم.
3. انشر الالتزام الجديد من الفرع المرتبط. إذا كان **Auto Deployment** مفعّلًا، يبدأ النشر بعد رفع الملفات إلى هذا الفرع.
4. بعد النشر افتح [فحص الخادم](https://domnamatchserver-jos7vara.back4.app/health). الاستجابة المتوقعة تتضمن `"ok":true` و`"development":false`. بعدها جرّب فتح المتصدرين وقبول دعوة بين حسابين في تطبيق DOMNA 2.0.

استخدم نفس رابط `MATCH_SERVER_URL` في إعدادات تطبيق Flutter طالما حدثت تطبيق Back4App الحالي. قواعد وفهارس Firebase الحالية تكفي لهذا التحديث.

يحفظ الخادم النتائج والترتيب في ملف `STATE_PATH`، وقيمته الافتراضية في Docker هي `/data/matches.json`. الاحتفاظ بالترتيب عند استبدال الحاوية يعتمد على تخزين دائم لهذا المسار. إذا عندك تخزين دائم وبيانات سابقة، احتفظ بنفس المسار ووحدة التخزين. شغّل نسخة واحدة من الخادم لكل ملف حالة.

للاختبار المحلي استخدم Dart 3.10، ومن مجلد `server` نفّذ `dart pub get --enforce-lockfile` ثم `dart test`. وثائق المضيف: https://www.back4app.com/docs-containers/prepare-your-deployment
